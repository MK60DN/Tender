## 摘要

教育组织中的很多问题表面上是“管理问题”，底层却是信息不对称下的博弈问题：

- 谁真正创造了教学价值，难以被准确观察；
- 谁在制造内耗、截取功劳或隐藏问题，也难以被及时识别；
- 老板、管理者、教师、学生和家庭各自掌握不同信息；
- 当“撒谎收益高、被发现概率低”时，理性个体会被激励去撒谎、防备和争夺分配权。

Tender 的长期机会不是再做一个教学工具，而是建立一层**可验证的信任与贡献基础设施**：

```text
非合作博弈中的信息不对称
→ 可验证事件、权限、审计与申诉
→ 改变收益矩阵
→ 形成更可信的合作联盟
→ 用合作博弈方法分配新增价值
```

本文明确区分三类内容：

1. **已经实现的产品能力**：DAOQL 事件、因果链、权限、哈希审计、心智化状态、多 Agent 对话；
2. **可以工程化的机制原型**：激励诊断、贡献度报告、Shapley 计算器、争议与复核流程；
3. **仍需研究和验证的命题**：生产级 BFT 共识、真实因果贡献、组织效率十倍提升。

> 真正能打动顶级投资人的，不是把“博弈论”当装饰，而是把机制约束、数据条件和不可承诺的边界同时说清楚。

## 一、为什么教育组织会陷入非合作博弈

### 1.1 从“个人道德”转向“制度激励”

把组织内耗解释为某个人“坏”通常没有产品价值。更有用的问法是：

> 在当前规则下，一个理性个体做什么最划算？

如果真实教学贡献难以观察，而汇报、包装和关系经营更容易被奖励，那么组织就会奖励“会展示的人”，而不是“真正创造价值的人”。

这不是道德判断，而是激励结构问题。

### 1.2 简化模型

设参与者为：

- 管理者或组织所有者 \(O\)；
- 中层管理者 \(M\)；
- 教师 \(T\)；
- 学生与家庭 \(L\)。

每个人选择：

- 真实投入并真实汇报；
- 降低投入但包装汇报；
- 隐藏问题或将责任转移给他人。

个人收益可写为：

```text
U_i = 直接收益
    + 虚报收益
    - 被发现概率 × 处罚
    - 协调与内耗成本
    + 共享价值分成
```

其中：

- `U_i`：参与者 \(i\) 的期望收益；
- `直接收益`：工资、绩效、地位或资源；
- `虚报收益`：通过不实汇报或归因获得的额外收益；
- `被发现概率`：组织识别不实信息的概率；
- `处罚`：被发现后的经济、声誉或制度成本；
- `协调与内耗成本`：防备、争夺、返工和沟通损耗；
- `共享价值分成`：组织整体变好后个人获得的部分。

当虚报收益很高、发现概率很低、处罚很轻时，非合作策略会成为纳什均衡。

### 1.3 为什么单纯“讲价值观”改变不了均衡

如果规则不变，只要求大家“坦诚协作”，通常会产生两个结果：

- 诚实者承担更高成本；
- 善于包装者继续获得收益。

因此，问题不是增加一次培训，而是改变收益矩阵。

## 二、机制设计：让真实贡献成为更划算的策略

### 2.1 机制设计的目标

一个可用的机制至少要同时考虑：

| 约束 | 含义 |
|---|---|
| 激励相容 IC | 说真话、做真实贡献的期望收益不低于操纵数据 |
| 个体理性 IR | 参与者愿意加入机制，而不是退出或绕过 |
| 预算平衡 BB | 分配规则在组织预算内可执行 |
| 可审计性 | 关键事件、权限、修改和申诉可以追溯 |
| 可纠错性 | 误判可以复核、申诉和撤回 |
| 隐私最小化 | 只收集完成机制所需的信息 |

### 2.2 一个简化的审计博弈

设：

- \(b\)：操纵信息带来的私人收益；
- \(p\)：被发现的概率；
- \(F\)：被发现后的处罚；
- \(s\)：个人从共享新增价值中获得的分成；
- \(V\)：合作创造的新增价值；
- \(u_0\)：真实贡献的基础收益。

真实汇报的期望收益：

```text
U_truth = u0 + sV
```

操纵信息的期望收益：

```text
U_lie = (1 - p)(u0 + b + sV) - pF
```

要让真实汇报成为更优选择，需要：

```text
U_truth >= U_lie
=> p(b + F) >= (1 - p)b
```

简化后可理解为：

> **被发现概率上升，或处罚与声誉成本上升，真实贡献的相对收益就会上升。**

Tender 的机制设计不是声称“系统让人变好”，而是让组织更容易验证真实行为，让真实贡献在收益上更有竞争力。

### 2.3 DAOQL 在机制中的作用

DAOQL 的作用不是替人做价值判断，而是提供可验证的事实层：

- 谁在什么时候提交了什么证据；
- 哪个 Agent 基于什么上下文给出了建议；
- 用户是否回复、执行、拒绝或静默；
- 贡献报告使用了哪一版规则；
- 谁修改、撤回或复核过记录；
- 每一次分配依据什么证据。

### 2.4 当前实现与未来扩展

| 能力 | 当前状态 | 边界 |
|---|---|---|
| 事件链 | 已实现 | 记录触发、建议、反馈和结果 |
| 因果图 | 已实现基础版本 | 表达关联和推理链，不自动证明因果 |
| 权限与租户隔离 | 已实现 MVP | 生产级 OIDC/RBAC 仍需完善 |
| 哈希审计链 | 已实现 | 可发现链内篡改，不能自动防止源头伪造 |
| 多角色签名与来源诊断 | 原型已实现 | 校验签名结果、统计独立来源组与来源类型；密钥托管和生产验签待接入 |
| 外部时间戳 | 规划 | 证明某记录在某时刻已存在 |
| BFT 阈值与复核门 | 原型已实现 | 实现 `n >= 3f+1`、`2f+1` 法定人数和来源多样性复核；默认关闭，仅在联盟阶段准入条件满足后启用 |
| 独立第三方审计 | 规划 | 争议解决与责任边界 |

> 当前最准确的表述是：**可追溯、可复核、哈希链式审计基础设施**。  
> **不能把当前的哈希链直接说成已经实现 BFT。**


### 2.5 防合谋：从三人死局到 3f+1 证据门槛

#### 1. 三人模型为什么会失效

拜占庭容错研究的是：在部分节点可能撒谎、掉线或发送矛盾消息时，系统能否仍然保持一致。

如果一共有 \(n=3\) 个节点，最多有 \(f=1\) 个作恶节点：

```text
n = 3
f = 1
3f + 1 = 4
```

由于 \(3 < 4\)，这个三人组不满足经典 BFT 的安全条件。假设 A 和 B 合谋，C 是诚实的：

- A 可以对 C 说“B 同意了”；
- B 也可以对 C 说“A 同意了”；
- A 和 B 对外给出彼此一致、但实际虚假的版本；
- C 只靠这三个人的口头消息，无法稳定判断谁在撒谎。

更准确地说，不是某个算法必然“自动把 C 踢出局”，而是：

> **在只有三个节点、允许一个节点作恶的条件下，系统无法同时保证安全和继续运行。**

这正是组织治理的产品启示：只让少数有利益关系的人互相证明，证据结构本身就不可靠。

#### 2. 增加独立见证者，而不是增加同源重复

经典 BFT 阈值是：

```text
最小节点数：n >= 3f + 1
法定人数：quorum = 2f + 1
```

其中：

- \(n\)：本轮有资格参与验证的独立节点数；
- \(f\)：系统希望容忍的最大作恶节点数；
- `quorum`：作出一项决定至少需要的有效确认数。

| 容忍作恶节点 \(f\) | 最小节点数 \(3f+1\) | 法定人数 \(2f+1\) |
|---:|---:|---:|
| 1 | 4 | 3 |
| 2 | 7 | 5 |
| 3 | 10 | 7 |
| 4 | 13 | 9 |

但“签名数量够”仍然不够。一个学校账号可以生成多个角色签名，或者三个签名都来自同一个后台。因此 Tender 的证据门同时检查：

```text
Q(e) = 1[|V(e)| >= 3f+1]
       × 1[|S(e)| >= 2f+1]
       × 1[|G(e)| >= 2]
       × 1[|T(e)| >= 2]
```

符号解释：

- \(e\)：同一个待确认事件或事实主张；
- \(V(e)\)：本轮有资格参与验证的独立节点或签署人名单；
- \(S(e)\)：完成有效签名的独立签署人集合；
- \(G(e)\)：这些签署人所属的来源组集合；
- \(T(e)\)：来源类型集合；
- \(Q(e)=1\)：达到“进入人工政策复核”的门槛；
- \(Q(e)=0\)：需要补充独立证据。

#### 3. 什么算独立来源

| 来源组 | 示例证据 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 学生交互 | 答题、停留、主动回复、任务提交 | 某次交互确实发生 | 不能独立证明教学贡献 |
| 教师交付 | 备课、课堂记录、作业反馈 | 某项教学动作被记录 | 不能证明学生已经掌握 |
| 家庭反馈 | 家长确认、投诉、补充说明 | 家庭侧观察和意见 | 不能替代过程证据 |
| 设备信号 | 可选授权的活动强度、睡眠或心率摘要 | 当时的上下文变化 | 不能当作“读心”或绝对客观真相 |
| 第三方审计 | 校方、监管方或独立审计者的复核 | 对争议程序的独立见证 | 仍可能犯错或受制度约束 |

这里的“独立”指**记录路径、权限边界和利益关系相互独立**，不指来源永远正确。

关键校正：

- 学生点击不等于认知负荷；
- 心率变化不等于情绪；
- 登录 IP 不等于人在现场；
- 家长确认不等于事实自动成立；
- 设备是补充证据，不是天然的“诚实节点”。

#### 4. 来源集中度

设来源组 \(g\) 的签署人数为 \(c_g\)，总签署人数为：

```text
C = Σ_g c_g
```

该来源组占比：

```text
share_g = c_g / C
```

Herfindahl 集中度指数：

```text
HHI = Σ_g (share_g)^2
```

解释：

- 来源越分散，HHI 越低；
- 单一来源占 100% 时，HHI 为 1；
- Tender 原型的复核触发规则是：只有一个来源组，或最大来源组占比不低于 80%；
- 高集中度只提高人工复核优先级，不自动判定某人合谋。

#### 5. 八步证据闭环

```text
1. 记录事件
   事实、时间、权限、规则版本
        ↓
2. 校验签名
   谁签了、签名是否有效、密钥是否属于本人
        ↓
3. 检查法定人数
   独立签署人是否达到 2f+1
        ↓
4. 检查来源多样性
   是否至少有两个来源组和两种来源类型
        ↓
5. 检查历史一致性
   与个人和班级基线比较，标记异常而不是定罪
        ↓
6. 人工复核
   查看证据、反证、规则版本和利益冲突
        ↓
7. 申诉与撤回
   被影响者可以质证、补充证据和申请复核
        ↓
8. 记录结论
   结论、责任主体、证据范围、有效期和后续动作
```

#### 6. 区块链能做什么，不能做什么

可以：

- 证明某条签名记录在某个时间点已经存在；
- 发现记录在链内被事后改写；
- 让多方持有同一份审计证据；
- 为争议留下可复核的时间顺序。

不能：

- 自动证明录入者说的是真话；
- 自动判断谁在合谋；
- 自动完成公平分配；
- 替代调查、申诉、司法或组织制度；
- 在没有真实多机构节点时冒充“联盟链”。

因此，Tender 的正确技术表述是：

> **多源证据、角色签名、法定人数、历史一致性与人工复核共同提高合谋成本。**

#### 7. 已实现的工程验收

当前 `mechanism_design.py` 已实现：

- `bft_threshold(f)`：返回 \(3f+1\) 和 \(2f+1\)；
- `evaluate_attestation_quorum(...)`：检查合格节点名单、签署人法定人数和来源多样性；
- `collusion_concentration(...)`：计算来源占比与 HHI 风险提示；
- 同一签署人的重复记录不增加独立签署人数；
- 同一签署人申报多个来源时触发 `signer_source_conflicts`；
- 合格节点名单少于 \(3f+1\) 时不满足门槛；
- 来源过度集中时只返回高优先级复核，不返回责任结论。

自动测试覆盖：

| 场景 | 预期 |
|---|---|
| \(f=1\) | 最小 4 个节点，法定人数 3 |
| 只有 2 个有效签名 | 不满足复核门槛 |
| 3 个签名但只有一个来源组 | 法定人数满足，来源多样性失败 |
| 合格名单只有 3 人、\(f=1\) | 不满足最小节点数 4 |
| 同一签署人申报两个来源 | 来源冲突，不能增加多样性 |
| 4 人合格名单、3 个签名、至少两个来源组和两种来源类型 | 可以进入人工政策复核 |
| 单一来源占 100% | 高优先级复核，不自动判责 |

截至 2026-10-29，全量 46 项测试通过。



### 2.6 分阶段治理：链下专家议会、联盟 BFT 与开放自治

Tender 不把“上链”当作第一天的产品能力。治理复杂度必须跟随真实网络的复杂度增长。

#### 阶段 A：链下专家议会

当前阶段采用实名专家议会：

```text
Agent 提出建议、摘要、证据与反例
                    ↓
实名专家分别表决并签名
                    ↓
DAOQL 记录理由、少数意见、规则版本和申诉
                    ↓
链下哈希审计与定期人工复核
```

议会至少覆盖教育、心理与神经认知、安全与未成年保护、数据合规、学习者或家庭代表、独立工程审计。

约束：

- 专家实名、履历、任期和利益冲突公开；
- 成员与主席按任期轮换，并发布决议理由和少数意见；
- 重大争议可提交独立复核；
- Agent 没有最终表决权；
- BFT 关闭；
- 外部锚定关闭；
- 原始数据留在链下；
- 争议可以复核、申诉和撤回。

阶段 A 的目的不是“永远不上链”，而是先证明：

- 教育判断是否有稳定证据；
- 专家之间是否能形成可解释的决议；
- 家长、学生和教师是否信任流程；
- 事件、权限、版本和申诉能否长期维护。

#### 阶段 B：Tanka 联盟与许可链 BFT

当 Tender 与 Tanka 及联盟伙伴建立真实的多机构合作关系后，才评估许可链 BFT。

进入门槛：

| 门槛 | 验收证据 |
|---|---|
| 合作与治理协议 | Tanka 与联盟伙伴签署的正式文件 |
| 验证者治理 | 名单、角色、利益冲突、退出规则 |
| 密钥安全 | 多方托管、轮换、失钥恢复演练 |
| 独立审计 | 安全与隐私审计报告，高风险项关闭 |
| 争议程序 | 申诉、撤回、人工复核和责任认定 |
| 故障演练 | 节点失联、分叉、密钥泄露和恢复 |
| 测试网周期 | 至少一个完整治理周期 |
| 数据边界 | 链上白名单与敏感数据黑名单 |
| 链下稳定性 | 专家议会达到预设质量和运营门槛 |

联盟 BFT 只保存：

- 承诺和审计根；
- 角色签名；
- 规则版本；
- 学习凭证哈希；
- 治理投票；
- 贡献报告哈希。

不保存：

- 原始对话；
- 心智状态推断；
- 健康与生理信号；
- 生物特征时间序列；
- 未成年人的身份资料；
- 原始学习事件。

这与“把所有数据搬上区块链”是两种完全不同的产品。

#### 阶段 C：开放验证者与全民自治

“全民自治”是一组制度能力，不是一条链的营销标签：

- 开放验证者的准入、质押、退出和惩罚；
- 可撤回委任，而不是一次性授权；
- 公开章程、规则版本、资金和审计；
- 少数意见与未成年保护；
- 申诉机制；
- 紧急权力的明确边界和日落条款；
- 参与率、代表性和决策质量达到门槛。

只有联盟 BFT 稳定运行并完成独立复审后，才允许进入开放自治。任何从专家议会直接跳到全面开放的方案，都应被治理门拒绝。

进入联盟阶段必须逐项通过规则，不允许仅凭一个配置开关启用 BFT。截至 2026-10-29，全量 46 项测试通过。

#### 对资本效率的意义

先链下、后联盟、再开放自治是一种更节约资本的路线：

- 不需要在需求与治理尚未验证时承担链上基础设施成本；
- 不必过早锁定共识协议和节点伙伴；
- 上链只在“多方共同见证”真的产生价值时发生；
- 每一阶段都能独立验收、回退和停止。

## 三、从非合作到合作：新增价值如何分配

### 3.1 合作博弈的基本问题

合作博弈不假设每个人单独作战，而是研究：

- 哪些人组成联盟；
- 联盟能创造多少总价值；
- 每个人对联盟的边际贡献是多少；
- 分配规则能否稳定联盟。

设参与者集合为：

```text
N = {1, 2, ..., n}
```

联盟价值函数：

```text
v(S), S ⊆ N
```

其中：

- \(S\)：一个参与者子集；
- \(v(S)\)：只有联盟 \(S\) 合作时能够实现的价值；
- 大联盟总价值：\(v(N)\)。

### 3.2 Shapley Value

参与者 \(i\) 的 Shapley 值为：

```text
φ_i(v) = Σ_{S ⊆ N\{i}}
         |S|!(n-|S|-1)!/n!
         × [v(S ∪ {i}) - v(S)]
```

符号解释：

- \(φ_i(v)\)：参与者 \(i\) 的期望边际贡献；
- \(S\)：不包含 \(i\) 的联盟；
- \(v(S ∪ {i}) - v(S)\)：加入 \(i\) 后联盟价值的变化；
- 权重：在所有加入顺序中，该边际贡献出现的概率。

Shapley 值满足：

- 有效性：所有贡献之和等于大联盟总价值；
- 对称性：同等边际贡献获得同等分配；
- 零贡献者：没有边际贡献的参与者得到零；
- 可加性：多个价值来源可以分别计算后相加。

### 3.3 为什么不能直接用分数变化算贡献

一个学生从 50 分提高到 80 分，不能简单按“班主任 20%、英语老师 30%”拍脑袋分。因为：

- 学生可能自己投入更多；
- 生源和基础不同；
- 教师之间可能互补；
- 时间、考试难度和家庭支持会变化；
- 分数只是结果，不是贡献本身。

Tender 的贡献报告只能是：

> **在明确价值函数和实验设计下，对边际贡献的估计。**

不能把预测模型直接当作因果归因。

## 四、价值函数怎么来

### 4.1 首选：随机对照与阶梯式上线

最可靠的方式是把学生或班级随机分配到不同支持组合，例如：

- 只有班主任；
- 班主任 + 学科教师；
- 班主任 + 学科教师 + 学习策略 Agent；
- 完整圆桌。

通过盲评、延迟测试和真实行动结果估计不同联盟的价值。

### 4.2 次选：自然实验与准实验

利用排课变化、教师更换、工具上线时间差异，做双重差分、断点回归或工具变量。

### 4.3 最后才是指标近似

在没有实验条件时，可以用以下信号构建低置信度近似：

- 延迟提取表现；
- 迁移题表现；
- 任务完成率；
- 行动恢复率；
- 同类错误复发率；
- 学生自评与外部观察。

但必须标注置信度和证据类型，不能把观察性关联写成因果结论。

## 五、贡献度审计报告

### 5.1 报告字段

```text
报告周期
参与者列表
联盟价值 v(S)
价值函数版本
数据来源与时间窗
每人 Shapley 值
贡献占比
置信区间
未解释残差
可能的替代解释
申诉与复核状态
```

### 5.2 报告输出示例

```text
总增量：+18 个稳定掌握点
班主任：+4.8，占比 26.7%
英语教师：+6.2，占比 34.4%
学习策略 Agent：+3.1，占比 17.2%
同伴互教：+2.4，占比 13.3%
未解释：+1.5，占比 8.3%
```

这些数字必须附带：

- 实验设计或估计方法；
- 置信区间；
- 适用周期；
- 归因边界。

### 5.3 申诉机制

任何贡献报告都必须允许：

- 查看原始事件；
- 对数据来源提出异议；
- 要求人工复核；
- 标记规则版本；
- 撤回错误证据；
- 记录规则变更。

没有申诉机制的“算法分配”会把技术权力变成新的黑箱。

## 六、产品架构：把机制设计落到系统

### 6.1 五层架构

```text
价值结果层
  延迟掌握、迁移表现、行动恢复、真实作品
        ↑
贡献分配层
  Shapley 计算、置信区间、申诉、规则版本
        ↑
博弈激励层
  信息验证、收益矩阵、处罚与声誉、隐私边界
        ↑
心智化 Agent 层
  状态假设、Triage、功能型专家、对话与复盘
        ↑
DAOQL 事实层
  事件、因果、权限、反馈、结果与审计链
```

### 6.2 关键数据对象

| 对象 | 作用 |
|---|---|
| `evidence_event` | 证明某个行为或结果发生 |
| `attestation` | 角色对同一证据的签名；记录来源组、来源类型、签名有效性和规则版本 |
| `coalition_outcome` | 某个参与者组合的共同结果 |
| `value_function_version` | 贡献计算使用的价值函数版本 |
| `contribution_report` | Shapley 值、占比、置信区间和边界 |
| `dispute_case` | 争议、复核和撤回记录 |

### 6.3 角色权限

- 教师：查看自己的证据和贡献解释；
- 班主任：查看授权班级的群体贡献；
- 管理者：查看组织级贡献与预算分配；
- 审计者：查看规则、证据和变更链；
- 学生与家庭：只查看与自身相关的摘要；
- 平台：不能默认读取原始私人对话。

### 6.4 与 Tender C 端的关系

博弈论机制主要是**组织治理与企业版本**能力，不应破坏 C 端学习体验。

建议采用双轨结构：

```text
C 端：心智化学习、环境型多 Agent、学习护照
B 端：组织版信任层、贡献审计、绩效辅助、争议复核
```

B 端是从 C 端长期证据自然长出的治理能力，而不是把 C 端变成监控工具。

## 七、机制设计的产品指标

### 7.1 非合作博弈指标

| 指标 | 含义 |
|---|---|
| 证据覆盖率 | 关键行为有多少被可验证记录 |
| 数据争议率 | 对数据真实性提出异议的比例 |
| 信息不对称指数 | 不同角色的信息可见性差距 |
| 内耗时间占比 | 用于解释、防备、重复沟通和争议的时间 |
| 真实汇报率 | 可验证记录与实际结果一致的比例 |
| 申诉闭环率 | 争议得到复核和关闭的比例 |

### 7.2 合作博弈指标

| 指标 | 含义 |
|---|---|
| 联盟总价值 | 合作后新增的真实学习结果 |
| Shapley 解释度 | 贡献报告能解释总增量的比例 |
| 未解释残差 | 模型或实验无法归因的部分 |
| 分配公平感 | 参与者对分配可解释性的评价 |
| 联盟稳定性 | 参与者的留存和继续协作意愿 |
| 争议后修复率 | 分配争议后恢复合作的比例 |

### 7.3 防止指标作恶

禁止：

- 用聊天时长代替教学贡献；
- 用频繁汇报代替真实结果；
- 用满意度代替延迟学习；
- 用一次考试代替长期掌握；
- 用 Shapley 值包装主观惩罚；
- 用审计系统监控私人生活。

## 八、研究路线与验证

### 阶段 1：可追溯

- 证明事件、证据、权限和结果可以被可靠记录；
- 建立规则版本与申诉流程；
- 验证哈希审计能发现链内篡改。

### 阶段 2：可验证

- 加入多角色签名和外部时间戳；
- 对关键贡献事件要求独立证据；
- 建立教师、学生和家庭的最小授权视图。

### 阶段 3：可估计

- 在小规模真实班级做随机对照；
- 估计不同支持组合的边际价值；
- 用精确 Shapley 计算小规模联盟分配。

### 阶段 4：可治理

- 把贡献报告接入绩效讨论，而不是自动扣款；
- 建立人工复核与争议解决；
- 测量分配规则对留存和协作的影响。

### 阶段 5：可共识

- 只有在 Tanka 与联盟伙伴真实参与、治理和密钥条件满足后，才启用联盟 BFT；
- 开放自治不能跳过联盟阶段，也不能取消申诉、隐私和少数保护；
- 不以“去中心化”替代实际治理；
- 不以“不可篡改”替代源头真实性。

## 九、顶级 VC 路演版叙事

> 各位投资人，教育行业真正昂贵的成本，很多时候不是内容成本，而是**信任成本和协调成本**。
>
> 当谁真正创造了价值无法被看见，组织中就会出现防御、包装、甩锅和反向激励。这不是某个人道德有问题，而是博弈规则让真实贡献不划算。
>
> Tender 做两层机制设计。
>
> 第一层，用 DAOQL 建立可追溯的事实、权限、因果、反馈和结果链。关键事件必须经过角色签名、法定人数和来源多样性检查；系统不会因为“同一个人签了三次”就把它当成三方共识。
>
> 第二层，用心智化模型和合作博弈方法，把学生真实进步、行动恢复和迁移结果作为联盟价值，估计教师、班主任、助教和 Agent 的边际贡献，生成带有置信区间、争议入口和申诉机制的贡献审计报告。
>
> 我们不承诺算法自动实现公平。我们提供的是：更少的信息不对称、更清楚的贡献证据、更可解释的分配讨论，以及一个可以被人复核的机制。
>
> Tender 的长期愿景，不是卖一个更聪明的教育工具，而是为教育组织建立一层**可验证的信任与贡献基础设施**。

## 十、商学院案例式结论

### 10.1 非合作博弈视角

教育组织的内耗不是单纯道德问题，而是：

```text
信息不对称
+ 贡献难验证
+ 惩罚概率低
+ 包装收益高
→ 真实投入的相对收益下降
→ 互相防备与向下倾轧
```

### 10.2 合作博弈视角

当真实结果和边际贡献可以被更清楚地记录：

```text
共同价值可被观察
+ 贡献可被估计
+ 分配可解释
+ 争议可复核
→ 合作联盟更容易维持
→ 新增价值更可能被继续创造
```

### 10.3 Tender 的机制价值

> **用事实层降低信息不对称，用 Agent 层降低理解成本，用贡献层提高分配可解释性，用申诉层保留人的最终裁决权。**

这句话比“AI 让教育效率提升十倍”更可靠，也更适合顶级投资人尽调。

## 十一、必须明确的研究边界

- Shapley 值不是“自动公平”，它只在你定义的价值函数下成立；
- BKT/AUC 是预测能力指标，不是教师因果贡献；
- 可追溯不等于真实，源头数据仍可能被伪造；
- 哈希链不等于 BFT，去中心化不等于可信；
- `n >= 3f+1` 只是阈值条件，生产级 BFT 还需要成员管理、密钥托管、视图切换、恢复和网络假设；
- 合格节点名单和来源角色映射必须由授权系统维护，否则签名数据仍可能被批量伪造；
- 来源多样性降低同源伪造风险，但不能排除多个来源同时观察错误或共同造假；
- 高集中度、异常和历史不一致只能触发复核，不能自动判定责任；
- 贡献报告不能自动决定薪酬、晋升或处罚；
- 任何绩效分配都要结合人工复核、申诉和制度约束；
- 未成年人和员工数据必须遵循最小必要、角色隔离和可撤回原则。

## 十二、建议的下一步实验

### 实验 G1：审计能否改变博弈

- A 组：传统汇报；
- B 组：DAOQL 证据 + 多角色确认；
- 指标：争议率、真实汇报率、协调时间、管理者判断准确率。

### 实验 G2：Shapley 报告能否提高分配可解释性

- A 组：传统绩效说明；
- B 组：Shapley + 置信区间 + 未解释残差；
- 指标：公平感、接受度、申诉率、联盟留存。

### 实验 G3：贡献归因是否稳定

- 用随机对照或准实验估计联盟价值；
- 比较 Shapley、回归归因和简单比例分配；
- 重点看跨周期稳定性和未解释残差。

### 实验 G4：C 端与组织版边界

- 验证学习护照是否能在不泄露私人内容的情况下生成组织级摘要；
- 验证用户是否愿意把部分长期证据用于组织贡献讨论；
- 验证“不默认共享原始对话”是否提高信任。


### 实验 G5：多源证据门能否识别同源伪造

- A 组：单方录入；
- B 组：单方录入 + 同源多角色签名；
- C 组：多源签名 + 法定人数 + 来源多样性；
- D 组：C 组 + 历史一致性 + 人工复核与申诉；
- 数据：预注册的合成争议案例和经过授权的审计演练数据；
- 主要指标：同源伪造识别率、误报率、复核时间、申诉接受率和参与者公平感；
- 禁止：用真实个人或未经证实的职场指控作为实验材料；
- 成功标准：C 组应显著减少同源签名通过率；D 组在降低误判的同时，不显著恶化复核效率。
