## 产品主张：连接自我、世界与他人心智

Tender 从温柔了解您的心智开始，再把理解转化为世界中的行动，把对他人的理解转化为有授权、可协商、可撤回的协作。

> **Tender：温柔地了解您的心智，也帮助您更好地进入世界、理解他人、参与协作。**  
> **从自我理解，到世界行动，到关系协商，再到共同结果。**

这句话的产品含义是：

| 说法 | 含义 |
|---|---|
| 温柔地了解您的心智 | 以尊重、克制和可撤回的方式，了解影响行动的状态与过程 |
| 授权范围 | 仅使用您明确授权提供的信息 |
| 可纠错假设 | 您拥有确认、补充、修改和撤回判断的权利 |
| 接住下一步 | 帮助您恢复行动，并逐步形成自主能力 |




## 三个价值回路

Tender 不把“更了解自己”当作终点。产品价值沿三条连续回路展开：

| 回路 | 用户问题 | 产品作用 | 可验证结果 |
|---|---|---|---|
| 自我回路 | 我现在的注意、负荷、动机、情绪和行动阻力是什么？ | 形成可更正的状态假设，帮助用户理解自己如何开始、卡住和恢复 | 用户纠错、状态解释质量、提示负担 |
| 世界回路 | 什么值得追求？下一步做什么？结果是否支持我的判断？ | 把理解转成最小行动，让真实结果、迁移和承担回流模型 | 行动恢复、预测误差、迁移、真实结果 |
| 关系回路 | 对方可能如何理解？我是否把推断当成了事实？ | 区分观察、解释和需要，支持表达、澄清、边界协商和修复 | 误归因率、关系修复、授权遵守 |
| 群体回路 | 我们是否在讨论同一问题？谁承诺了什么？决定是否闭合？ | 通过群公开事实、共享枝和 Group Model 形成可确认的共同结果 | 承诺闭合、决策闭合、未解决问题 |

### 四个具体场景

1. **一个人开始不了任务**：Tender 先判断是任务入口过大、注意漂移、情绪负荷还是身体疲劳，再给一个最小行动；结果返回后修正判断。
2. **孩子和家长产生误解**：孩子保留完整私密模型，只授权最小必要摘要；Tender 帮双方区分事实、推断和需要，不输出关系匹配分。
3. **项目组讨论停滞**：Group Model 识别开放问题、承诺缺口和决策状态；Group Facilitator 只提协调问题，不替成员发言。
4. **两个合作者建立共享枝**：共同目标、任务和承诺经过参与者批准后进入共享枝；私人情绪和完整生命树保持隔离。

因此，Tender 的核心价值可以写成：

> **让自我理解进入世界行动，让对他人的理解进入关系协商，让协作留下可验证的共同结果。**

## 让 AI 成为森林的气候，让人成为生命树的作者

> **生命不是被某个框架评价出来的形状，而是在有限时间里，通过选择、关系、承担和创造长出来的年轮。**

现有培养体系过于庞大，并且伴随人的一生。它提供秩序，也带来持续的压力和对未知的恐惧。外部标准一旦变成人的内在边界，一个人可能很会解决问题，却逐渐失去对自己生命的解释权。

Tender 要做的，是一层贯穿终身的心智生长环境：

- 在压力出现时，帮助人命名压力；
- 在未知面前，帮助人把恐惧拆成可以理解和行动的风险；
- 在选择面前，帮助人看见自己真正重视什么、愿意承担什么；
- 在行动之后，帮助人保存结果、复盘和形成自己的价值证据；
- 在自主能力增强之后，逐步退到背景，把解释权和决定权归还给人。

生命树是这套系统的叙事与建模语法：

| 生命树 | 人的成长 | Tender 如何承接 |
|---|---|---|
| 种子 | 尚未展开的可能性 | 不用一次测评定义一个人 |
| 根系 | 安全、关系、身体状态与真实反馈 | 先理解支持条件，再讨论表现 |
| 树干 | 长期选择与承担形成的连续性 | 记录跨时间的承诺、行动和结果 |
| 枝叶 | 探索、试错、跨域连接与角色经验 | 提供多 Agent 视角，不替人规定方向 |
| 开花 | 第一次有足够证据看见自己的整体成长 | 用长期证据形成可更正的状态假设 |
| 结果 | 独立迁移、创造作品、影响他人并承担后果 | 关注真实结果和迁移，而非奖励等级 |
| 森林 | 不同生命在同一生态中互相支撑 | 保持多样性，拒绝把人修剪成同一种形状 |

AI 可以模拟风雨，却不能替一棵树长出年轮；它可以提供地图，却不能替一个人决定要去哪里。

这里的“成熟”，指一个人能够理解自己的状态，选择值得追求的事情，承担选择后的结果，在需要时调整、求助并重新出发。

Tender 的中心主旨是：

> **让 AI 成为森林的气候，让人成为生命树的作者。一个人不必成为最聪明的那个，也不必成为最有用的那个，他仍然可以通过自己的选择、关系、创造和承担，长成独一无二的生命形态；也通过行动、协作和共同结果，进入更大的森林。**

生命树是叙事与建模语法。具体科学主张仍需通过真实数据、预注册实验和独立复核验证；Tender 不把模型输出当作诊断，也不承诺替代考试或保证结果。

## 日常界面：只有弹幕和底部对话条

日常使用时不打开任何网页。桌面端只保留：

1. 屏幕上方透明 Agent 弹幕层；
2. Windows 任务栏正上方的常驻对话输入条。

用户可以直接在底部输入条提问，按 Enter 发送。发送后，输入条上方会展开一个临时对话抽屉，显示完整、自然的专家回复；弹幕只保留短摘要和即时提醒。

对话抽屉接入真实大模型：Triage Agent 先路由，相关专家再结合最近对话历史生成自然回复。规则模板只在模型不可用时作为安全回退，不再是默认对话主体。

网页界面作为内部预览和调试入口，不属于日常产品体验。

## 产品交付模型：一套核心，三类界面

Tender 不把 B 端和 C 端做成两套底层产品，而是采用“同一核心、三类交付界面”。

```text
共享核心
DAOQL · 语言证据 · Tender 状态 · 生命树 · 知识森林
Agent Runtime · 授权 · 安全 · 审计
        │
        ├─ B 端完整系统：Tender 提供教育系统
        ├─ B 端嵌入模块：Tender 融入合作方教育系统
        └─ C 端自有界面：Tender 融入用户生活
```

### B 端完整系统

适用于希望由 Tender 统一承接核心教育业务的机构。系统覆盖招生、排课、考勤、教学交付、班主任工作台、执行校长绩效、财务、学情、家长沟通和组织报表。

### B 端嵌入模块

适用于已有 LMS、SIS、CRM、教务、家校或企业培训系统的机构。合作方保留原有界面与系统记录，Tender 通过 API、SDK、事件契约、单点登录、对象权限和审计接口嵌入语言证据、Tender 状态、知识森林、专业 Agent 与风险治理。

嵌入模式必须满足：

- 不复制合作方全部数据库；
- 只读取完成明确任务所需的最小事件；
- 机构账号与个人账号分离；
- 机构记录进入个人学习护照前必须取得用户授权；
- 合作方系统仍是其业务记录源时，不制造第二份互相冲突的“真相”。

### C 端自有界面

C 端由 Tender 提供自己的界面，包括移动端、网页、桌面环境层、任务栏上方对话条和低频弹幕。它围绕个人学习、工作、转行、兴趣探索与长期成长持续存在，不依附于某一所学校或机构。记录归属于用户，可导出、暂停、撤回和删除。

### 数据与商业边界

| 关系 | 默认数据边界 |
|---|---|
| 机构购买完整系统 | 机构拥有组织运营数据，不等于拥有学习者全部心智记录 |
| 机构嵌入 Tender | 合作方保留原有业务数据，Tender 仅处理明确授权的任务事件 |
| 个人使用 C 端 | 个人拥有自己的学习护照与长期记录 |
| 机构与个人关联 | 必须由用户授权，支持随时撤回 |

## 如何使用这份手册

这份手册不按“公司介绍—功能清单—愿景”来写，而是按产品经理真正做产品的顺序展开：

```text
发现机会
→ 定义用户与问题
→ 形成产品假设
→ 比较方案
→ 收敛 MVP
→ 设计旅程与信息架构
→ 写需求与验收标准
→ 设计多 Agent 与数据
→ 做实验与指标
→ 安排上线与迭代
```

每一步都回答五个问题：

1. 我看到了什么事实？
2. 我做了什么判断？
3. 我选择了什么方案？
4. 我放弃了什么？
5. 用什么证据证明这一步没有自嗨？

> 这不是一份“证明 Tender 很厉害”的材料。它是一份让新产品经理能接手、能挑战、能继续迭代的工作文档。

## 第 0 步：机会判断——先确认到底值不值得做

### 0.1 最初看到的表面问题

学习者经常说自己：

- 看不进去；
- 学不进去；
- 坚持不下来；
- 不知道从哪里开始；
- 学了很久还是不会；
- 一考试就发挥不好。

这些描述很常见，但都不能直接变成需求。因为它们同时混合了知识、注意力、情绪、任务设计、身体状态和环境因素。

### 0.2 把模糊抱怨改写成可设计的问题

产品问题被重新定义为：

> **当学习者处于真实学习流程中时，系统能否在最少打扰下识别一个最可能的卡点，调用正确的专业视角，给出一个可立即执行的最小动作，并用真实结果验证这次帮助是否有效？**

这个定义包含五个可设计对象：

| 对象 | 要回答的问题 |
|---|---|
| 状态识别 | 现在可能发生了什么 |
| 时机 | 现在值不值得打扰 |
| 专业视角 | 应该由谁来说 |
| 最小动作 | 用户下一步到底做什么 |
| 结果验证 | 这次帮助是否真的产生了变化 |

### 0.3 机会为什么成立

机会成立不是因为“AI 很热”，而是因为现有产品普遍缺失一段流程：

```text
内容很多，但不知道此刻该做什么
测评很多，但结果不能指导下一步
聊天很多，但不会在真实场景里主动出现
数据很多，但用户不能带走
提醒很多，但不验证是否有效
```

### 0.4 这一步的产出

- 机会陈述：从“学习困难”收敛为“卡点识别—专业支持—行动验证”闭环；
- 产品边界：不是内容平台，不是考试系统，不是心理诊断工具；
- 首要验证问题：低打扰的多 Agent 帮助是否能提高行动恢复率。

### 0.5 这一步不做什么

- 不先做课程商城；
- 不先做封闭、不可集成的机构 ERP；B 端能力必须围绕共享核心、完整系统与嵌入模块展开；
- 不先做排名和分数预测；
- 不先追求“Agent 数量最多”；
- 不把用户停留时长当作目标。

## 第 1 步：用户细分——不是所有学习者都是同一类用户

### 1.1 第一层：核心用户

**自主学习者，约 15–25 岁，覆盖高中、大学和职业早期。**

典型任务：

- 准备考试或证书；
- 完成课程作业；
- 长期学习一项技能；
- 在目标专业与当前能力之间找差距；
- 需要有人帮助自己维持行动，但不想被监控。

### 1.2 第二层：授权家庭用户

家长不是默认查看全部数据的人，而是经授权获得最小必要摘要的人。

他们真正需要的不是“孩子今天学了几分钟”，而是：

- 是否在持续行动；
- 是否出现需要支持的异常；
- 本周有哪些真实进步；
- 下一步家庭可以怎么配合。

### 1.3 暂不优先的用户

| 用户 | 为什么暂不优先 |
|---|---|
| 学校管理者 | 作为 B 端完整系统或嵌入模块的购买与治理角色单独设计，不混入 C 端个人体验 |
| 培训机构销售 | 容易把产品做成招生工具 |
| 低龄儿童 | 授权、安全和家长依赖更复杂 |
| 临床心理人群 | 需要医疗级评估与转介流程 |

### 1.4 用户画像：一个具体的人

**林同学，高二，目标计算机专业。**

她的问题不是“没有题做”，而是：

- 数学错题反复出现，但不知道自己卡在概念还是计算；
- 一焦虑就切换到短视频；
- 晚上困了还硬撑，第二天更差；
- 家长只能看到“今天没学多久”；
- 她不想被监控，但愿意接受自己授权的提醒。

### 1.5 这一步的产出

- 核心用户与非目标用户；
- 学习者的真实任务链；
- 家庭只获得授权摘要；
- 后续所有需求都必须回到“林同学此刻能不能多做一步”。

## 第 2 步：需求洞察——把“想要功能”还原成任务

### 2.1 用户任务（Jobs To Be Done）

| 情境 | 用户真正想完成的任务 |
|---|---|
| 打开材料却迟迟不开始 | 把任务缩到可以开始 |
| 做错后不知道原因 | 判断卡在知识、策略还是状态 |
| 学了很久却不确定是否掌握 | 用短提取或迁移验证 |
| 情绪上来后回避 | 降低威胁，恢复一个最小动作 |
| 身体疲劳却硬撑 | 识别该休息还是该继续 |
| 目标专业很遥远 | 把长期目标拆成当前能力差距 |
| 被提醒后觉得烦 | 快速纠正、静默、退出 |
| 家长想帮忙 | 获得最小必要、不过度侵入的摘要 |

### 2.2 需求优先级

使用“频率 × 损失 × 可验证性 × 隐私成本”判断：

| 需求 | 频率 | 损失 | 可验证性 | 隐私成本 | 结论 |
|---|---:|---:|---:|---:|---|
| 开始困难 | 高 | 高 | 高 | 低 | P0 |
| 错因不清 | 高 | 高 | 高 | 中 | P0 |
| 注意力漂移 | 高 | 中 | 高 | 中 | P0 |
| 情绪回避 | 中 | 高 | 中 | 高 | P0，但低置信度 |
| 身体疲劳 | 中 | 中 | 中 | 中 | P1 |
| 专业目标差距 | 低 | 高 | 中 | 低 | P1 |
| 家庭摘要 | 中 | 中 | 中 | 高 | P1 |
| 专家 Agent 市场 | 低 | 中 | 低 | 高 | P2 |

### 2.3 一个关键判断

用户不是需要“更多建议”，而是需要：

> **在正确时刻，由一个合适的专业视角，给出足够小、可以马上验证的帮助。**

这直接否定了“把所有专家 Agent 同时叫出来说很多”的设计。

## 第 3 步：产品假设——先写出可以被推翻的话

### 3.1 核心假设

| 编号 | 假设 | 如何验证 |
|---|---|---|
| H1 | 低打扰环境提示能提高行动恢复率 | 随机对照：有提示 vs 无提示 |
| H2 | 功能型多 Agent 比单 Agent 提供更多有效覆盖 | 盲评内容覆盖率与非冗余率 |
| H3 | 两条并发弹幕比八条同时出现负荷更低 | 主观负荷、阅读时间、负反馈 |
| H4 | 用户回复后的个性化回应优于单向弹幕 | 回复组 vs 非回复组行动恢复率 |
| H5 | 隐私归一化足以支持基础行为判断 | 分类准确率与用户接受度 |
| H6 | 用户删减 Agent 后体验更好 | Agent 数量与留存、打扰疲劳 |

### 3.2 反假设

必须同时写出产品可能错在哪里：

- 用户可能根本不愿被任何环境 Agent 监测；
- 多 Agent 可能只是热闹，没有真实增量；
- 行为信号可能不足以判断学习状态；
- 弹幕可能从帮助变成新的干扰；
- 用户可能只在新奇期使用；
- Agent 回复可能让用户更依赖，而不是更独立。

### 3.3 这一步的产出

- 可证伪的产品假设；
- 每个假设对应的实验和指标；
- 明确的产品失败条件。

## 第 4 步：目标与非目标——先画边界

### 4.1 产品目标

1. 减少用户从卡住到行动的摩擦；
2. 让帮助在真实软件环境中出现；
3. 用不同专业视角减少误判；
4. 用最小反馈和真实结果持续校准；
5. 把长期学习证据归还给用户。

### 4.2 非目标

- 不做完整课程平台；
- 不替代教师、心理咨询师或医生；
- 不承诺提分；
- 不通过制造焦虑提高留存；
- 不做社交排名；
- 不用停留时长证明价值；
- 不把用户所有数据都上传云端。

### 4.3 产品原则

| 原则 | 具体含义 |
|---|---|
| 最小帮助 | 一次只解决一个当前最重要的问题 |
| 可解释 | 能说明为什么出现 |
| 可纠正 | “不是这样”必须改变下一次行为 |
| 可退出 | 静默、清空、关闭都是正常选择 |
| 低负荷 | 多 Agent 但最多两条并发 |
| 证据优先 | 不把满意度当成学习效果 |
| 隐私最小化 | 原始窗口标题不离开本机 |
| 去羞耻化 | 不把卡点解释为懒惰或人格缺陷 |

## 第 5 步：方案空间——先比较，再选择

### 5.1 备选方案

| 方案 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| 传统学习 App | 可控、功能清晰 | 用户卡住时不会主动打开 | 不作为主形态 |
| 通用 AI 聊天 | 实现快、表达自然 | 仍需用户主动提问，缺少时机 | 作为底层能力，不做主入口 |
| 浏览器插件 | 容易获取页面上下文 | 只覆盖浏览器，权限敏感 | 后续补充 |
| 手机系统助手 | 触达强 | 平台限制和隐私成本高 | 暂不优先 |
| 桌面悬浮层 | 跨软件、可控制打扰、易做 MVP | 仅 Windows 先行 | 当前选择 |
| 可穿戴设备 | 连续生理信号 | 成本高、生态依赖强 | 后续合作 |
| 多 Agent 同时刷屏 | 看起来丰富 | 认知负荷高 | 否决 |
| 两条并发、其余排队 | 兼顾覆盖和可读性 | 需要队列管理 | 当前选择 |

### 5.2 决策 D01：从桌面悬浮层切入

原因：

- 能覆盖浏览器、文档、网课等真实学习环境；
- 不要求用户离开当前软件；
- 可以用鼠标穿透保证不挡操作；
- 可以先在 Windows 上验证，不需要等待手机系统能力。

### 5.3 决策 D02：多 Agent 不等于多消息

原因：

- 用户面对多个同时出现的建议会产生选择负荷；
- 功能覆盖和同时呈现是两件事；
- 可以在后台保留 8 个 Agent，但前台最多显示两条。

## 第 9 步：功能需求与用户故事

### 9.1 P0：桌面环境弹幕

**用户故事：** 作为学习者，我希望在浏览器、文档或网课上方看到帮助，而不必切换应用。

**验收标准：**

- 独立进程运行；
- 始终置顶；
- 无边框；
- 鼠标穿透；
- 不抢焦点；
- 屏幕最多同时两条 Agent 弹幕；
- 其他 Agent 自动排队；
- 浅灰半透明底、黑色文字。

### 9.2 P0：本地行为归一化

**用户故事：** 作为学习者，我希望系统理解我所在的任务类型，但不希望它上传我的原始窗口标题。

**验收标准：**

- 本地识别应用类别；
- 本地提取短任务提示；
- 只发送 `app_category`、`task_hint`、空闲、切换和活跃度；

- 不截图、不读正文、不读剪贴板、不启用音视频。

### 9.3 P0：功能型多 Agent

**用户故事：** 作为学习者，我希望同一情境能从学习策略、学科、注意力、心理、营养和生涯角度得到不同意见。

**验收标准：**

- 至少 8 个功能型 Agent；
- Agent 输出内容非冗余；
- 每个 Agent 的功能、角色和触发依据可解释；
- 营养、心理、神经认知建议明确不是诊断；
- 安全保护官可触发高风险升级。

### 9.4 P0：两路队列

**用户故事：** 作为学习者，我希望知道多个 Agent 都在场，但不想同时阅读八条消息。

**验收标准：**

- 顶部显示全部在场 Agent；
- 屏幕上最多两条并发；
- 默认每条停留后自动移出；
- 队列自动接力；
- 用户可按 `Ctrl+Alt+0` 清空。

### 9.5 P0：反馈与回复

**用户故事：** 作为学习者，我希望一条建议不合适时能快速纠正，也希望能继续对话。

**验收标准：**

- `Ctrl+Alt+1` 有用；
- `Ctrl+Alt+2` 不合适；
- `Ctrl+Alt+3` 静默 30 分钟；
- `Ctrl+Alt+R` 打开回复框；
- 回复后由功能型 Agent 生成简短回应；
- 回复、反馈和结果写入 DAOQL。

### 9.6 P1：学习护照

**用户故事：** 作为学习者，我希望长期看到自己在哪些情境更容易行动、哪些帮助更有效。

**验收标准：**

- 展示时间、情境、Agent、建议、用户动作和结果；

- 支持删除和撤回；
- 不展示不必要隐私内容；

### 9.7 P2：专家 Agent 与市场

**用户故事：** 作为高级用户，我希望购买或出售经过审核的专家 Agent。

**前置条件：**

- 有稳定的 AgentSpec；
- 有权限隔离；
- 有内容审核；
- 有交易与责任审计；
- 有高风险类别的人工复核。

## 第 10 步：多 Agent 产品设计——谁在什么情况下说什么

### 10.1 功能型 Agent 定义

| Agent | 负责什么 | 不负责什么 |
|---|---|---|
| 学习策略师 | 拆任务、定优先级、设计复习节奏 | 不判断医学或心理状态 |
| 学科专家 | 知识点、先修、错因和最小练习 | 不替代完整课程 |
| 神经认知师 | 注意力、工作记忆、负荷和恢复 | 不诊断注意力缺陷 |
| 心理调节师 | 焦虑、回避、动机和自我评价 | 不做心理诊断 |
| 营养健康师 | 睡眠、饮食、补水和身体状态 | 不开营养处方 |
| 生涯规划师 | 专业兴趣、长期目标和能力证据 | 不替用户填志愿 |
| 安全保护官 | 隐私、身心安全和求助边界 | 不做普通学习建议 |
| 元认知教练 | 策略觉察、监控和复盘 | 不替用户承担选择 |

### 10.2 Triage Agent：先判断这是什么问题

系统先运行一个独立的 Triage Agent，把用户消息和当前行为信号转成结构化判断：

```text
user_message + behavior_signals
→ problem_type
→ confidence
→ risk_level
→ evidence
→ alternative_explanation
→ routed_agent_ids
```

Triage Agent 的职责是“分诊”，不是直接给建议。只有分诊完成后，相关专家才会被调用。

| 用户表达 | 分诊结果 | 被调用的专家 |
|---|---|---|
| “我很焦虑” | 焦虑与情绪负荷 | 心理调节师、神经认知师 |
| “这道数学题不会” | 知识或错因卡点 | 学科专家、学习策略师、元认知教练 |
| “我困得看不进去” | 疲劳与身体状态 | 营养健康师、神经认知师 |
| “我又开始刷视频了” | 注意力与任务切换 | 神经认知师、学习策略师 |
| “专业和选科怎么选” | 专业与生涯路径 | 生涯规划师、学习策略师 |
| “报名还没确认” | 报名与高利害流程 | 安全保护官、学习策略师、生涯规划师 |

示例：

> 用户说“我很焦虑”时，系统调用心理调节师和神经认知师，学科专家保持静默。

Triage Agent 的输出必须带置信度、证据、替代解释和风险等级。低置信度时，系统先问一个最小澄清问题，不贸然调用专家。

路由完成后，相关专家通过真实大模型生成 3–6 句自然回复，并带入最近对话历史。两位专家并行生成，对话抽屉异步更新，避免界面卡住；模板回复只在断网或模型失败时回退。

### 10.3 路由逻辑

```text
行为信号 + 当前场景 + 用户回复
→ Triage Agent 判断问题类型与风险
→ 选择相关专家
→ 只为相关专家生成内容
→ 最多两条并发
→ 其余相关意见排队
```

### 10.4 场景与主视角

| 场景 | 优先 Agent |
|---|---|
| 视频/游戏停留、频繁切换 | 神经认知师或学习策略师 |
| 错题、知识点不清 | 学科专家 |
| 情绪回避、羞耻 | 心理调节师 |
| 困、饿、头痛、眼疲劳 | 营养健康师 |
| 报名、隐私、流程风险 | 安全保护官 |
| 目标专业与当前能力 | 生涯规划师 |
| 策略无效、反复卡住 | 元认知教练 |

### 10.5 反冗余规则

两条建议如果表达同一意思，应合并。语义冗余：

```text
R_t = 2 / [N_t(N_t - 1)] * Σ(i<j) cos(v_i, v_j)
```

- `N_t`：本轮消息数；
- `v_i`：第 `i` 条建议的语义向量；
- `cos(·)`：语义相似度；
- `R_t`：本轮冗余程度。

产品目标不是让每个 Agent 都必须说一句，而是让不同视角真正提供新增信息。

### 10.6 为什么最多两条

这是尚未被实验最终证明的产品先验：

- 一条用于当前主问题；
- 一条用于互补视角或安全边界；
- 其他排队；
- 用户可通过删减 Agent 降低信息密度。

验证指标：主观负荷、阅读时间、负反馈、行动恢复率。

### 13.4 组织版的防合谋与贡献核算

这是同一套 DAOQL 事实层面向组织场景的扩展，不改变 C 端“了解心智、接住下一步”的主体验。

先说清楚边界：

> Tender 不把哈希链冒充 BFT，也不把异常检测冒充有罪判决。

组织版只做四件事：

1. 记录关键事件的原始证据；
2. 让不同来源独立签名；
3. 检查签名人数、来源组和来源类型；
4. 把冲突送入人工复核、申诉与撤回流程。

#### BFT 复核门槛

经典阈值：

```text
最小节点数：n >= 3f + 1
法定人数：quorum = 2f + 1
```

证据门同时要求：

```text
Q(e) = 1[合格节点名单 >= 3f + 1]
       × 1[独立签署人数 >= 2f + 1]
       × 1[来源组数量 >= 2]
       × 1[来源类型数量 >= 2]
```

`Q(e)=1` 只表示“可以进入人工政策复核”，不表示“某个人有罪”。同一签署人不能通过填写多个来源组来增加独立性。

| 来源组 | 可以提供的证据 | 产品边界 |
|---|---|---|
| 学生交互 | 答题、任务提交、主动回复 | 点击不等于掌握 |
| 教师交付 | 备课、课堂记录、反馈记录 | 记录不等于效果 |
| 家庭反馈 | 家长确认、投诉、补充说明 | 一方意见不能替代过程 |
| 设备信号 | 可选授权的活动、睡眠或心率摘要 | 不是读心，也不是绝对客观 |
| 第三方审计 | 对争议程序和证据的复核 | 仍需申诉和制度约束 |

来源集中度：

```text
HHI = Σ_g (c_g / C)^2
```

`c_g` 是来源组 `g` 的签署人数，`C` 是总签署人数。单一来源占 100% 时，HHI 为 1；产品只提高复核优先级，不自动判责。

#### 工程实现与验收

```text
agent_layer/app/mechanism_design.py
  bft_threshold(f)
  evaluate_attestation_quorum(...)
  collusion_concentration(...)
  shapley_values(...)
  contribution_report(...)
```

验收事实：

- 容忍 1 个作恶节点时，最小节点数为 4，法定人数为 3；
- 只有 2 个有效签名时，不满足法定人数；
- 3 个签名都来自同一来源组时，来源多样性失败；
- 合格节点名单少于 4 人时，即使有 3 个签名也不满足 \(f=1\) 的 BFT 门槛；
- 同一签署人申报多个来源时，产生来源冲突，不能增加独立性；
- 至少两个来源组、两种来源类型时，才进入人工政策复核；
- 单一来源占 100% 时，返回高优先级复核，不返回责任结论；
- 截至 2026-10-30，全量 114 项测试通过。

#### 与 Shapley 贡献报告的关系

Shapley 值回答的是：

```text
在已经定义好的联盟价值函数下，
每个参与者的平均边际贡献是多少？
```

它不能回答：

- 谁的人品更好；
- 哪个老师一定造成了分数变化；
- 哪个管理者应该被处罚；
- 哪一方在合谋。

因此，贡献报告必须同时展示：

- 所用价值函数和规则版本；
- 证据范围和缺失数据；
- 置信区间或不确定性；
- 未解释残差；
- 申诉与人工复核入口。

#### 对外一句话

> Tender 用多源证据、角色签名、法定人数、历史一致性和申诉机制，提高组织里伪造与合谋的成本；最终责任判断仍由可质证的人工流程完成。


### 13.5 三阶段治理路线：链下专家议会 → 联盟 BFT → 开放自治

Tender 当前不上链。上链不是产品成熟度的装饰，而是多个独立机构需要对同一份承诺形成共同见证之后，才值得引入的结算层。

#### 阶段 A：链下专家议会（当前）

教育场景先采用“实名专家议会 + 可审计 Agent 建议”：

| 角色 | 职责 |
|---|---|
| 教育专家 | 判断学习目标、任务难度和效果证据 |
| 心理与神经认知专家 | 解释注意、负荷、情绪和风险信号 |
| 安全与未成年保护负责人 | 处理高风险事件和未成年人权益 |
| 数据合规与隐私负责人 | 审核数据边界、授权和删除机制 |
| 学习者或家庭代表 | 对影响用户的规则提出质询 |
| 独立工程审计 | 检查事件链、权限和模型版本 |

Agent 只提供建议、摘要和反例，不参与最终表决。

专家议会同时遵守：

- 专家实名、履历和任期公开；
- 每次议题前披露利益冲突并回避；
- 成员与主席按任期轮换；
- 发布决议理由、证据范围和少数意见；
- 重大争议可提交独立复核；
- 定期接受外部工程、隐私与安全审计。

阶段 A 的能力边界：

- DAOQL 与哈希审计链保留在链下；
- 使用实名签署、权限隔离、版本记录和申诉流程；
- 不启用 BFT，不启用外部锚定，不向用户宣称“已上链”；
- 先验证教育效果、争议处理、数据最小化和运营稳定性。

#### 阶段 B：与 Tanka 及联盟伙伴启用 BFT

只有在与 Tanka 及联盟伙伴完成正式合作、治理章程和节点协议后，才进入联盟 BFT 阶段。

准入条件：

- Tanka 合作与治理协议签署；
- 验证者名单、角色和利益冲突登记完成；
- 多方密钥托管、轮换和失钥恢复方案通过评审；
- 独立安全审计完成，高风险项关闭；
- 争议、申诉、撤回和人工复核流程可运行；
- 节点失联、分叉、密钥泄露和恢复演练通过；
- 联盟测试网完成至少一个完整治理周期；
- 链上链下数据边界通过隐私与合规评审；
- 链下专家议会连续运行并达到预设质量门槛。

进入后，BFT 只处理：

```text
承诺 commitment
签名 attestation
审计根 audit_root
规则版本 rule_version
学习凭证哈希 credential_hash
治理投票 governance_vote
贡献报告哈希 contribution_report_hash
```

#### 阶段 C：开放验证者与全民自治

全民自治不是“所有事情都投票”，也不是取消专家和申诉。它需要：

- 开放验证者的准入、质押、退出和惩罚规则；
- 公开治理章程与可撤回委任；
- 少数意见、未成年人和家庭权利保护；
- 申诉机制与紧急权力的日落条款；
- 真实参与率、代表性和决策质量达到门槛；
- 代码、规则、资金和治理记录可独立审计。

只有联盟 BFT 稳定运行并完成独立复审后，才评估进入开放自治；禁止从链下专家议会直接跳到全民自治。

#### 永不默认上链的数据

| 数据类型 | 处理方式 |

| 心智状态推断 | 链下、可更正 |
| 健康与生理信号 | 链下、最小必要 |
| 生物特征时间序列 | 链下 |
| 未成年人身份 | 链下、严格授权 |
| 原始学习事件 | 链下 |

### 13.6.1 语言检测与 Tender 建模

这里的“语言检测”不是判断中文或英文，也不是从一句话直接读出人格、能力或疾病。它负责从话语中提取带来源的证据片段：显式情绪、不确定性、回避、自我效能威胁、对他人心智的推断、校准偏差、求助、任务请求和安全风险词。

```text
原始话语
→ 语言脚本与证据片段
→ 多个竞争假设
→ 与答题、行为、时间、结果、历史和关系情境融合
→ 最小行动
→ 真实结果回流与校准
```

最小融合式：

```text
S_t = f(L_t, B_t, K_t, R_t, H_t, C_t)

L_t = 语言证据
B_t = 行为与响应
K_t = 知识作答
R_t = 真实结果
H_t = 历史基线
C_t = 当前关系与任务情境
```

#### 三个组件各自做什么

| 组件 | 适合承担 | 不能承担 |
|---|---|---|
| 语言模型 | 结构化抽取、语义检索、候选解释、自然表达 | 宣布知识掌握、人格类型、临床诊断或事实真相 |
| Tender 状态模型 | 融合多源证据，更新带不确定性的状态假设 | 把一句话当唯一证据，绕过真实结果 |
| 确定性规则 | 高风险路由、来源校验、阈值、禁止输出和审计 | 理解复杂反讽、引用与长期变化 |

#### 语言层不能单独决定什么

- “我不行”不能推出能力低或人格缺陷；
- “我焦虑”不能推出焦虑障碍；
- “我不想学”不能推出懒惰或长期动机不足；
- “这题我会”不能更新知识掌握度；
- 一次表达不能成为永久用户标签。

知识掌握度只根据作答和任务结果更新。语言信号用于理解当前表达、选择支持方式、提出验证问题和调整 Agent 路由。


接口输出：

- 语言脚本与原文位置；
- 特征向量与证据片段；
- 竞争假设、置信度和替代解释；
- 下一次验证问题与建议回应模式；
- 高风险保护路由和禁止结论边界。

### 13.7 首次预检测：八功能世界入口与动态大五

#### 13.7.1 产品原则

预检测不是人格判决，也不是给用户一个 MBTI 类型。所有用户完成同一套结构化评估，系统在后台决定两件事：

1. 用户当前更自然地先进入客观世界、主观世界，还是从真实卡点桥接进入；
2. 用户近期需要多少结构、探索、关系协调、恢复和现实验证。

用户界面不显示 MBTI 字母、荣格功能代码或固定类型名称。用户只看到自然语言结果，例如“你更容易先建立内部理解，再做现实测试”。

#### 13.7.2 题目结构

| 模块 | 题量 | 用途 |
|---|---:|---|
| 八功能态度 | 24 | 每种功能 3 题，严格覆盖两种态度 × 四种功能 |
| 大五基线 | 20 | 心理资源基线、支持偏好和注意成本 |
| 大五短脉搏 | 10 | 每周或关键关系事件后观察变化、波动和恢复 |

内部八功能矩阵：

|  | 感觉 | 直觉 | 思维 | 情感 |
|---|---|---|---|---|
| 外倾态度 | Se 现实观察 | Ne 可能性探索 | Te 结果执行 | Fe 关系协调 |
| 内倾态度 | Si 经验对照 | Ni 长期整合 | Ti 结构建模 | Fi 价值边界 |

每个功能使用连续分数和三题一致性。一致性低时，降低该功能对支持策略的影响，不强行解释。

#### 13.7.3 世界入口

系统比较外倾功能平均分与内倾功能平均分：

- 客观入口优先：先给事实、任务、资源和结果反馈；
- 主观入口优先：先给框架、价值、假设和内部模型；
- 桥接入口优先：从一件真实卡点同时记录事实与解释。

入口只决定提问顺序、任务组织、例子和 Agent 支持，不进入知识掌握、认知能力 θ、考试预测或职业命运。

#### 13.7.4 大五脉搏

大五从一次性标签改为时间序列：

```text
个人基线
→ 近期脉搏
→ 变化幅度
→ 波动与恢复
→ 关系与沟通支持
```

十题脉搏记录开放、尽责、外向、宜人和情绪稳定性的近期变化，可附关系、角色、任务、时段和简短说明。支持示例：

- 外向性低于基线：社交电量可能下降，优先异步和短互动；
- 宜人性低于基线：可能在建立边界，不能解释为敌意；
- 尽责性低于基线：缩小承诺、写清检查点；
- 情绪稳定性低于基线：降低评价威胁，先给可控下一步；
- 开放性低于基线：先连接熟悉经验，再引入变化。

变化不等于人格永久改变。脉搏只用于沟通、负荷、协作和恢复。

#### 13.7.8 动态黄金比偏置律

黄金比不作为每日 KPI。系统把它定义为带滞回的弹性带：

- 学习和创造中较小一极长期不低于约 38.2%；
- 较大一极长期不高于约 61.8%；
- 7 天窗口用于短期提示；
- 28 天窗口用于阶段判断；
- 证据不足时不输出比例结论；
- 只有连续偏离才进入观察和提示，连续回到带内后解除。

计算同时使用三类指标：

| 指标 | 含义 | 用途 |
|---|---|---|
| 投入比 | 学习与创造的滚动时间/事件权重 | 判断吸收和输出是否长期失衡 |
| 新异比 | 输出中真正产生新分支的比例 | 识别重复或过度发散 |
| 创造后校准比 | 输出后 72 小时内是否出现反馈、复测或结果校验 | 防止创造脱离现实 |

接口：

```text

```

用户界面只显示自然语言，例如：

不显示“黄金比分数”，不将比例用于人格、能力、关系匹配或绩效排名。

#### 13.7.9 节律相位与周期证据

7 天和 28 天仅是系统的观察与控制窗口，不是用户真实周期。V2.0 新增独立的周期证据层：

| 问题 | 产品处理 |
|---|---|
| 用户有没有稳定周期 | 从 84 天每日学习—创造序列估计 5—28 天候选周期 |
| 周期是否只是随机波动 | 与置换零分布、自相关强度和反相位证据比较 |
| 周期是否确定 | 分为证据不足、无稳定周期、候选周期、稳定周期 |
| 用户当前在哪个相位 | 吸收与编码、整合与巩固、表达与分叉、现实校准、恢复或低活动 |
| 是否直接生成日程 | 不生成；候选周期只用于试探性支持，稳定周期也要保留反证空间 |

接口继续使用：

```text
GET /golden-bias/{student_id}
```

新增返回：

```text
rhythm.operating_windows
rhythm.detected_periodicity
rhythm.current_phase
rhythm.phase_sequence
rhythm_phase
```

用户界面只显示自然语言，例如：

- “当前更像吸收与编码阶段，先完成一个最小输出。”
- “周期证据还不足，暂不把最近波动写成固定周期。”
- “检测到一个候选周期，但还只是待验证假设，不会变成固定日程。”
- “近期活动减少，可能是恢复，也可能是阻塞，先确认再介入。”

周期估计不能用于人格、能力、绩效、关系匹配或临床判断。恢复与低活动必须保持不确定性。

#### 13.7.10 实验证据与产品边界

V2.0 完成 4 个实验臂、每臂 1,000 名合成学习者、84 天的机制实验。动态规则使用阶段目标和滞回。结果显示：

- 相对不调节：行动恢复和带内时间提高；
- 相对固定 50:50：提示负担约减半，恢复相近；
- 相对固定阈值：恢复和带内时间提高，但提示更多，创造后校准没有提高。

V2.0 合成周期实验得到 95.3% 的周期检出率、93.3% 的容忍范围内估计、0.45 天平均绝对误差、7.0% 的非周期稳定周期误报率和 100% 的五类受控相位分类准确率。产品结论仍是“负担感知的节律权衡”，不是“动态黄金比或周期检测全面胜出”。完整实验见 `Tender-Golden-Bias-Experiment-v1.0.pdf` 和 `Tender-Rhythm-Phase-Experiment-v1.0.pdf`。下一步必须做预注册真人研究，并保留不调节、固定 50:50、固定阈值和动态规则四个对照。

#### 13.7.11 双链路与多人聊天后台

Tender 正式区分两条共享同一后台底座、但数据作用域不同的链路：

| 链路 | 目标 | 主要对象 | 不允许发生的事 |
|---|---|---|---|
| 单人链路 | 维护个人完整心智模型并支持下一步行动 | 私密事件、自我模型、Decision Loop、世界树 | 不把完整私密状态自动分享给他人或群 |
| 群聊链路 | 支持多人协作、澄清、承诺与共享结果 | 群公开事件、授权视图、他者假设、共享枝、群组成果 | 不建立读取所有人私密状态的全知群体模型 |

| 模型 | 归属 | 输入 | 输出边界 |
|---|---|---|---|

| `OtherModel(A→B)` | A 的 Tender | A 自己的观察、群公开互动、B 的授权摘要 | A 对 B 的关系假设，不是 B 的真实模型 |

### 13.8 Agent 上下文注入：让回答真正使用 Tender 建模

此前 Agent 只拿到最近对话和 Triage 标签，无法回答“我现在是什么状态”以及“为什么给这个建议”。现在每次 Agent 回复前都会构建一个有界 `tender_context`。

#### 上下文来源

```text
首次预检测
  八功能世界入口、大五基线、大五脉搏、注意成本与认知矫正

Tender 状态模型
  掌握度、元认知偏差、犹豫、安排匹配、情绪上下文

心智化假设
  当前主要假设、证据、支持方式

DAOQL 最近事件
  作答、响应时间、反馈、行动、结果

最近对话
  当前用户消息与上一轮 Agent 回复
```

#### 证据优先级

```text
当前用户消息与真实结果
→ 近期行为与行动结果
→ Tender 状态假设
→ 预检测人格与注意成本先验
```

预检测只是先验，不能覆盖用户刚刚说的事实。数据冲突时，Agent 必须说明不确定。

#### 状态问题路由

当用户询问：

- “我现在什么状态？”
- “我怎么了？”
- “我现在该怎么办？”
- “帮我看看当前状态。”

Triage 会生成：

```text
problem_type = state_review
```

并路由到：

- 元认知教练；
- 神经认知师；
- 学习策略师。

高风险词仍优先进入安全保护流程。

#### Agent 回答要求

- 先给 1–2 个最可能的状态假设；
- 说明使用了哪些近期证据；
- 明确这些是假设而非诊断；
- 给一个最小可执行行动；
- 用行动结果修正下一次判断；
- 不向用户暴露内部字段名、模型和编排流程。

#### 有界上下文

系统只带入：

- 最多 3 个心智化假设；
- 最近 12 条事件摘要；
- 最近 8–10 轮对话；
- 最多 3 个认知矫正练习；
- 当前状态的关键数值。

DAOQL 可以保存长期历史，但 Agent 不完全加载历史，避免上下文膨胀和注意污染。

```text

  format_tender_context()

```

回复卡记录：

```text

  context_version
  event_count
  preassessment_available
  attention_available
  mentalization_summary
  hypothesis_count
```

### 13.11 DAOQL 客观世界与生命树主观体验

Tender 把“发生了什么”和“这件事如何被体验”分成两层。

| 层 | 回答的问题 | 数据结构 |
|---|---|---|
| DAOQL 客观层 | 谁在什么时间做了什么，来源和证据是什么 | 原始事件、时间、来源、证据、版本、审计 |
| metameta 主观体验层 | 这个事件在生命树中可能意味着什么 | 体验节点、脑图区域、记忆类型、置信度、不确定性 |

新增 Agent `metameta_cartographer`（心智图谱标注师）读取客观 DAOQL 事件，但不修改原事件。它生成两类派生记录：

- `subjective_experience_node`：一次事件被拆解到的大脑图区域节点，例如工作记忆、海马体索引、长期记忆、内省反馈、情绪或代谢治理；
- `subjective_experience_summary`：一次客观事件对应的体验摘要，保存主区域、最多 6 个标签、生命树阶段和派生的体验节点 ID。

DAOQL 关系边明确区分事实和解释：

```text
客观事件 --experienced_as--> 主观体验节点
客观事件 --yields_subjective_experience--> 体验摘要
体验摘要 --contains_experience_node--> 体验节点
体验节点 --索引/编码/内省/表达等关系--> 体验节点
```

每个主观节点记录：

- `epistemic_status = subjective_experience`；
- `derived = true`；
- 客观来源事件 ID；
- 区域、颜色、半球位置；
- 匹配证据词和模型版本；
- 置信度与不确定性；
- 生命树阶段：根系、树干、枝叶、开花或结果。

接口：

```text
POST /metameta/decompose/{student_id}
GET  /metameta/map/{student_id}
```

Tender 上下文会分别报告客观事件来源数和主观体验节点数。体验节点可以更正、重算和撤回，不能反过来改写客观事件，也不能当作脑区扫描或临床诊断。

## 第 14 步：指标与实验——什么才算真的有效

### 14.1 北极星指标

**经过验证的行动恢复率。**

定义：

```text
ActionRecovery =
  在提示后 10 分钟内出现可验证行动的回合数
  / 被展示提示的回合数
```

“可验证行动”包括：

- 完成一个最小步骤；
- 提交一段复述；
- 做出一道同类题；
- 主动回复并说明下一步；
- 明确选择休息并在一段时间后恢复。

### 14.2 核心指标

| 指标 | 说明 | 目标方向 |
|---|---|---|
| 提示接受率 | 选择“有用”的比例 | 上升 |
| 误打扰率 | 选择“不合适”的比例 | 下降 |
| 行动恢复率 | 提示后真的行动 | 上升 |
| 同类卡点复发率 | 同一问题再次出现 | 下降 |
| 静默与退出率 | 用户主动关闭 | 先观察，非越低越好 |
| 多 Agent 有效覆盖 | 是否提供新增专业视角 | 上升 |
| 语义冗余率 | Agent 重复程度 | 下降 |
| 两路队列完成率 | 排队弹幕是否被看到 | 上升 |
| 学习护照留存 | 长期查看和导出 | 上升 |
| 自主性 | 后续所需提示减少 | 上升 |

### 14.3 实验设计

#### E1：单 Agent vs 两路多 Agent

- A 组：单 Agent 单条；
- B 组：多 Agent 两路队列；
- 主要指标：行动恢复率；
- 次要指标：主观负荷、负反馈、理解度；
- 结论标准：只有 B 组在行动恢复上更好且负荷可接受，才保留多 Agent 默认。

#### E2：两条并发 vs 六条同时出现

- A 组：两条队列；
- B 组：六条同时出现；
- 主要指标：主观负荷、阅读完成率、行动恢复率；
- 风险：六条组可能提升覆盖但降低使用意愿。

#### E3：营养/心理/认知 Agent 的增量

- 逐步加入功能型 Agent；
- 测量新增视角是否被使用、是否提升覆盖、是否增加冗余；
- 如果只增加字数不增加行动，应移除或降低出现频率。

#### E4：回复 vs 不回复

- A 组：只显示弹幕；
- B 组：允许用户回复；
- 主要指标：行动恢复率、后续自主性、依赖风险。

#### E5：固定 7 天、无周期与开放周期搜索

比较三种基线：固定 7 天假设、无稳定周期假设、开放周期搜索。主要终点为周期估计误差、非周期误报率、候选周期弃判率和相位分类准确率；次要终点为用户是否误解为固定日程、提示负担和纠错率。合成结果显示开放搜索优于固定 7 天假设，但仍有 7.0% 的非周期稳定周期误报，因此产品必须保持候选状态和可撤回表达。下一步应进行获得授权、可撤回的真实纵向数据预注册研究。

#### E6：群聊双链路隔离与共享枝

比较无授权、有限授权、撤回授权和共享枝批准四种状态。主要终点为私密数据越权读取数、他者模型误归因率、撤回后派生模型失效时间、共享枝审批完整率、Agent 自动发送数和用户纠错率。工程验收要求私密数据越权读取数和自动发送数均为 0；未来真人群体研究仍需独立伦理审查和预注册。

### 14.4 实验伦理

- 不制造必须使用才能获得好处的压力；
- 不把功能型 Agent 包装成临床专家；
- 用户可随时退出实验；
- 所有研究性结论标注证据等级；
- 不用用户沉默或停留时长代替真实行动。

| 隐私担忧 | 不愿安装 | 原始标题不上传、可关闭、可审计 |
| 用户过度依赖 | 自主性下降 | 逐步减少提示、鼓励自我复盘 |
| 只有新奇效应 | 留存下降 | 长周期实验和真实行动指标 |
| Agent 内容重复 | 用户觉得吵 | 语义冗余指标和合并规则 |
| 安全事件 | 高后果 | 安全保护官、人工审核、紧急转介 |
| 机构化诱偏 | 产品失去个人 C 端 | B 端完整系统、嵌入模块与 C 端独立交付；机构数据与个人护照分账；C 端保留退出与导出权 |
| 同源签名伪装成多方共识 | 错误信任 | 来源组 + 来源类型双门槛 |
| 在产品尚未成熟时提前上链 | 成本、合规与信任风险 | 链下专家议会先行，联盟条件满足后再启用 |
| 把全民自治理解为无约束投票 | 少数权利和安全性受损 | 开放验证者、权利保护、申诉和日落条款 |
| 把语言模型包装成神经模型 | 科学误导与信任损失 | 研究先验、行为弱信号和运行时推断严格分层 |
| 使用受限神经数据违反协议 | 合规与声誉风险 | 仅离线校准、数据使用协议和访问审计 |
| 用点击或穿戴数据诊断 | 标签伤害 | 只输出带置信度的竞争假设 |
| 用八功能入口定义用户能力 | 宿命感与歧视 | 只用于入口和支持假设，不进入能力评分 |
| 人格预检测保存逐题原文 | 隐私与二次使用风险 | 默认只保存标准化分数 |
| 把认知矫正做成临床治疗 | 越界与伤害风险 | 只做策略练习，设置安全退出和专业转介 |
| 同时矫正太多模式 | 负荷过高、用户挫败 | 一次只练一个模式，两次成功后淡出 |
| Agent 把上下文当确定诊断 | 错误标签与过度自信 | 先给假设、证据和不确定性 |
| 全量历史反复进入 Prompt | 成本高、干扰当前判断 | 有界上下文与最近事件摘要 |
| 用户当前消息与历史模型冲突 | 回答脱离当下 | 当前消息和真实结果优先，必要时更新模型 |
| 知识节点匹配错误 | 建议脱离课程内容 | 无命中不虚构，保留置信方式并允许用户纠正 |
| 课程库版本落后 | 建议过时 | 记录官方来源和版本，由教研人员复核 |
| 节点掌握度缺少作答映射 | 无法定位具体薄弱点 | 作答事件必须记录 node_id |
| 把异常当裁决 | 冤错与申诉风险 | 只触发复核，不自动判责 |
| 把 Shapley 当因果真相 | 错误分配 | 公开价值函数、残差、置信区间和申诉入口 |

## 第 20 步：这一版产品的最终定义

**Tender 是一款温柔地了解用户心智状态，并由功能型多 Agent 接住下一步的环境型学习系统。它不要求学习者每天打开操作页面，而是在授权范围内本地归一化最少必要的行为状态，在值得帮助时调用学习策略、学科、神经认知、心理、营养、生涯、安全和元认知等不同专业视角；屏幕上最多同时出现两条灰色半透明弹幕，其他 Agent 自动排队；用户可回复、静默或退出，系统用真实行动和长期结果持续校准帮助。**

产品经理的工作并没有结束。下一阶段最重要的不是再增加 Agent，而是回答：

> 多 Agent 是否真的比单 Agent 更有用？两条并发是否真的优于八条同时出现？用户是否变得更独立，而不是更依赖？

只有这些问题被真实数据回答，V6.17 才算从“可运行的产品设计”走向“被验证的产品”。组织版机制则要单独回答：多源证据是否真的降低争议、提高可解释性，同时没有制造新的黑箱裁判。
