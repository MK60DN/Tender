# 为什么 Tender 要用一组 Agent 协作

一个学生说：“我不想学了。”

这句话可能有很多层。任务太大，知识点缺了一块，最近太累，害怕被评价，目标已经不属于自己，或者只是此刻需要停一下。

如果只有一个“大而全”的 AI，它往往会马上给出一个综合答案。可综合得太早，真实原因反而容易被盖住。

Tender 用一组岗位明确的 Agent，让不同角度先各自工作，再把信息交给用户和人类支持者判断。

## 每个 Agent 像一个岗位

一个岗位需要说明自己负责什么、能看什么、能做什么，以及什么时候必须停下来。

Tender 里的 Agent 也要有这些说明：

- 负责哪类任务；
- 可以访问哪些授权数据；
- 可以调用哪些工具；
- 哪些动作需要人类确认；
- 必须引用哪些证据；
- 遇到什么情况要升级给现实中的支持者。

岗位清楚，协作才容易审计，用户也更容易知道自己正在和谁打交道。

## Agent Bridge 把事件翻译成体验

生命树的树干是 Agent Bridge。

它接收 DAOQL 里的客观事件，把它翻译成可以讨论的体验假设：

- 这次停顿更像任务启动困难，还是知识缺口？
- 这次回避更像害怕评价，还是身体疲劳？
- 这次求助更适合先给提示，还是先回应情绪？

Bridge 会同时给出证据和不确定性。它帮助人看见“可能意味着什么”，又给后续对话留下修正空间。

## 不同专家分别看见不同部分

同一个“我不想学了”，可以交给不同视角：

- 学习策略师：把任务拆小，寻找下一步；
- 神经认知师：观察注意、记忆负荷和疲劳信号；
- 心理调节师：理解威胁、羞耻和情绪需要；
- 生涯规划师：检查目标与个人方向是否仍然一致；
- 安全保护官：识别高风险信号，推动现实求助。

这些视角彼此独立，再通过 Bridge 汇总。比起让一个 Agent 同时扮演所有角色，这种做法更容易发现遗漏，也更容易追查每条建议的来源。

## Persona 负责表达，规则负责底线

Agent 可以有不同说话方式：有的温和，有的直接，有的像教练，有的像顾问。

说话风格可以变化，证据标准、安全规则和权限约束要保持一致。一个 Agent 用温柔语气提出建议，仍然需要说明依据；一个 Agent 用强硬语气推动行动，也不能越过用户授权。

## 人类保留最后决定权

Agent 可以整理信息、提出假设、准备草稿、检查计划和提醒风险。

涉及隐私、资源分配、自动发送消息或高风险判断时，需要人类确认。用户要能暂停、撤回、修改，并在出错后找到责任路径。

好的 Agent 会让人的判断更有依据，也会让人保留拒绝和改变方向的能力。
